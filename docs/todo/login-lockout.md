# 登录限流自锁 DoS 与防爆破加固（待办）

> **纯规划文档**：P0/P1/P2 均未实施。
>
> 来源：管理面公网部署场景讨论（2026-08-04）
> 现状：限流按 IP 不按账号、客户端 IP 取 TCP 层 ConnectInfo（不信 XFF）、内存态不落库
> 原则：消除「攻击者让管理员自己登不了」的一切路径，同时不削弱防爆破

---

## 1. 问题分析

### 1.1 现状语义（已确认）

- `core::util::LoginRateLimiter` key 为 **IP**（`crates/core/src/util.rs:98`）：5 次/分钟/IP、连续失败 5 次锁 15 分钟。攻击者刷 admin 账号锁的是**他自己的 IP**，经典「账号锁定 DoS」不存在。
- 客户端 IP 取 `ConnectInfo<SocketAddr>`（`crates/node/src/api/extractors.rs:157`），**不信任 X-Forwarded-For**，无法伪造头换 IP 绕过。

### 1.2 两个真实误伤场景

| 场景 | 机理 | 后果 |
|------|------|------|
| **反代/CDN 前置**（挂域名典型拓扑） | 回源后所有请求源 IP 都是 127.0.0.1 / 边缘 IP，限流退化为全局单 IP | 攻击者刷 5 次 → 127.0.0.1 锁定 → **含管理员在内的所有人锁 15 分钟**，攻击持续则无限续杯 |
| 同出口 NAT | 攻击者与管理员共享出口 IP | 连坐锁定 15 分钟 |

### 1.3 反向问题：防爆破强度

- IPv6 攻击者持有整个 /64，逐 IP 限流等于不限；botnet 分布式慢爆同理。per-IP 只是减速带。
- 失败登录**只进内存限流器、不落审计**，管理员对被爆破一事完全无感知。

### 1.4 最终兜底（已具备）

本机 root 永远有路：`anet admin reset-password --offline` 重置 + 重启清内存限流，不存在「永远登不了」的死局。

---

## 2. 实施计划

### P0 — 文档：推荐部署拓扑（wiki）

管理面不裸挂公网写入部署文档：API 绑 `127.0.0.1`，管理走带内（SSH 转发 / relay 暴露控制面 `psk_xxx|expose`），公网只露 relay 端口（TLS 拟态 + 首帧非法回 400）。必须挂域名时，限流上移到边缘（nginx `limit_req` / Cloudflare Rate Limiting），边缘按真实客户端 IP 限速。

### P1 — 代码：消除自锁 + 可观测（本轮目标）

1. **锁定期内「正确密码放行」**：`LoginRateLimiter` 锁定不再直接拒绝，改为「锁定状态下仅拒绝密码验证失败的请求」。攻击者不知密码，锁定对其依旧生效；管理员被 NAT/反代连坐时仍能登录。改动点：`crates/core/src/util.rs`（返回锁定状态而非硬拒）+ `crates/node/src/api/handlers/auth.rs` 登录 handler（锁定标志与密码验证结果联合判定，随机延迟惩罚保留）。
2. **失败登录落审计**：`admin.login_failed`（带 IP、带用户名、**严禁记密码**）写入 `audit_log`，管理端/TUI 可见爆破行为。改动点：`auth.rs` 登录失败分支。

### P2 — 纵深（后续批次）

- IPv6 限流 key 按 /64 聚合，堵地址轮换；
- 登录页 N 次失败后出验证码（Turnstile 类），替代硬锁体验；
- 失败事件打 tracing 日志（带 IP），支持 fail2ban 防火墙层封禁；
- refresh token 端点限流复核（与本次限流重构一并处理）。
