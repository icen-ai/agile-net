# 同步与备份

同步与备份回答一个问题：**换一台设备，配置怎么跟过去**。它把应用设置、自定义规则与 hosts、订阅列表与覆写脚本打成一份带版本号的存档，经由你自选的通道上传到远端；另一台设备填入同样的通道配置，一键拉取恢复即可。三个通道任选其一：

- **WebDAV**：坚果云、Nextcloud 等，最省事的个人方案
- **S3 兼容存储**：AWS S3、MinIO、Backblaze B2、Cloudflare R2，适合已有对象存储的用户
- **手动导入导出文件**：不依赖任何网络服务，U 盘、聊天软件传文件皆可

入口在 **设置 → 同步与备份**。

## 同步什么、不同步什么

| 同步 | 不同步 |
| --- | --- |
| 应用设置（角色开关、偏好） | Web 远程面密码（本机密钥，逐机设置） |
| 自定义规则与 hosts | mihomo 控制面 secret（本机随机值，无迁移意义） |
| 订阅列表与覆写脚本 | 本机凭据（扇入 token 存系统凭据库，不随存档走） |

## 快速上手（以坚果云 WebDAV 为例）

第一台设备（上传方）：

1. 打开 设置 → 同步与备份，通道选 **WebDAV**，填入坚果云的 WebDAV 地址、账号与**应用密码**（开通方法见下文「WebDAV 详解」）。
2. 按需设置一个 4 位数字 PIN（留空则不加密，权衡见「加密说明」）。
3. 点「立即上传」。上传成功后可见版本号 +1（如 v1 → v2），即存档已落到远端。

第二台设备（恢复方）：

1. 同样进入 设置 → 同步与备份，填入**完全相同的**通道配置与 PIN。
2. 点「拉取恢复」前先读版本比对：显示「远端更新」即可放心拉取。
3. 确认恢复。应用会先把现有配置自动备份到本地，再应用存档并**自动重启**生效。

两台设备此后各按需要上传；建议固定一台主力机负责上传，原因见「常见问题」。

## 通道详解：WebDAV

| 配置项 | 含义 | 示例 |
| --- | --- | --- |
| URL | WebDAV 目录地址，存档固定放在该目录下 | `https://dav.jianguoyun.com/dav/AgileNet/` |
| 账号 | 服务账号（坚果云为注册邮箱） | `you@example.com` |
| 密码 | **应用密码**，不是登录密码 | 16 位应用授权码 |

**坚果云应用密码怎么开**：登录坚果云网页版 → 右上角账号 → 账户信息 → 安全选项 → 「第三方应用管理」→ 添加应用密码。存档建议放在独立目录（如 `/dav/AgileNet/`），目录不存在时应用会尝试创建。

**Nextcloud**：WebDAV 地址形如 `https://<你的域名>/remote.php/dav/files/<用户名>/AgileNet/`，密码同样建议使用 Nextcloud 的「应用密码」（设置 → 安全 → 应用与设备会话）而非主密码。

远端文件名固定为 `agile-net-sync.json`，位于所配 URL 目录下。

## 通道详解：S3 兼容存储

| 配置项 | 含义 | MinIO 示例 | Cloudflare R2 示例 |
| --- | --- | --- | --- |
| Endpoint | 服务地址（不含 bucket） | `http://192.168.1.10:9000` | `https://<accountid>.r2.cloudflarestorage.com` |
| Bucket | 桶名 | `anet-backup` | `anet-backup` |
| Access Key / Secret Key | 访问凭据 | MinIO 控制台创建 | R2 「管理 API 令牌」创建 |
| Region | 区域，部分服务必填 | `us-east-1`（MinIO 默认） | `auto` |
| Prefix | 桶内路径前缀，可空 | `sync/` | `sync/` |

存档落在 `bucket/prefix/agile-net-sync.json`。

**权限最小化建议**：为同步单独建一个桶、单独一对 AK/SK，只授予该桶的读写权限（`s3:GetObject` / `s3:PutObject` / `s3:DeleteObject`，作用域限定 `arn:aws:s3:::anet-backup/*`），不要复用有高权限的主账号密钥。

## 通道详解：手动导入导出

不配置任何远端，直接走文件：

- **导出**：点「导出存档」，得到一份 `agile-net-sync.json`，拷到 U 盘、经聊天软件发给另一台设备皆可。
- **导入**：在目标设备点「导入存档」选中该文件，效果等同拉取恢复（同样先做本地自动备份再重启生效）。

文件名固定，不含版本号；**版本号写在文件内容里**，导入前应用会读出存档版本、时间戳与来源设备名供你确认。设了 PIN 的存档导出后仍是密文，导入时需要同样的 PIN。

## 版本号与时间戳怎么读

每份存档带三项元信息：**版本号**（整数，每次上传 +1）、**时间戳**（上传时刻）、**设备名**（上传方机器名）。

- **判断上传是否成功**：看版本号是否 +1（如 v3 → v4），时间戳是否刷新。
- **拉取前的版本比对**：

| 比对结果 | 含义 | 建议 |
| --- | --- | --- |
| 远端更新 | 远端版本号高于本地 | 可以拉取 |
| 本地最新 | 两边一致 | 无需操作 |
| 本地更新 | 本地版本号高于远端（本机改过还没传，或远端被旧存档覆盖） | 别拉，先确认哪边是对的 |

## 加密说明与安全建议

设一个 **4 位数字 PIN**，存档即以 AES-256-GCM 加密上传（密钥由 PIN 经 PBKDF2 派生）；留空则上传明文存档。

**请如实理解 4 位 PIN 的保护强度**：它只有一万种组合，是**混淆级保护**——防的是随手翻看你网盘目录的人，防不住有心人下载存档后离线暴力穷举。因此：

- 存档内容包含订阅列表，若订阅链接本身敏感，**建议配合私有 WebDAV 目录或自管的桶使用**，不要把未加密存档放进共享/公开目录。
- PIN **不设找回**：忘记 PIN = 存档无法解密，只能在还记得配置的设备上重设 PIN 后重新上传。
- PIN 逐设备输入、不落远端；换 PIN 后需重新上传，旧存档仍是旧 PIN 加密。

## 恢复与回滚

**恢复时本地配置不会被直接丢弃**：每次拉取/导入恢复前，应用自动把当前配置完整备份到：

```
~/.agile-net/backup-pre-restore-<时间戳>/
```

恢复完成后应用**自动重启**使配置生效。

**手动回滚**：若恢复结果不满意，退出 AgileNet，把对应时间戳备份目录里的文件拷回 `~/.agile-net/` 覆盖，再启动即可。备份目录按时间戳排列，可找到历史上任意一次恢复前的状态；空间紧张时可自行删除较旧的目录。

## 常见问题

**两台设备同时改了配置，冲突怎么办？**
同步是「最后写入胜出」：远端永远只保留一份最新存档，后上传的覆盖先上传的，没有逐字段合并。建议固定一台主力机负责上传，其余设备只拉取；临时在其他设备上改了重要配置，改完立即上传，并避免在两台设备上并行编辑。

**换机迁移清单**：

1. 旧设备：确认已上传最新存档（版本号为最新）。
2. 新设备：装 AgileNet → 填同样的通道配置与 PIN → 拉取恢复。
3. 逐项补回**不随存档走**的部分：Web 远程面密码重新设置；凭据（节点登录凭据、扇入 token）重新登录/导入；mihomo 控制面 secret 由新设备自动生成，无需处理。

**同步失败排查**：

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| 401 / 认证失败 | 账号或应用密码错（WebDAV 用了登录密码而非应用密码；S3 的 AK/SK 填反） | 重新生成应用密码 / 核对凭据 |
| 403 / 权限不足 | S3 策略未覆盖该桶或该前缀；WebDAV 目录无写权限 | 按「权限最小化建议」核对策略 |
| 网络超时 | 代理环境下同步流量被送进了代理，而代理本身不可用 | 同步请求固定走直连，不经过系统代理；请检查本机出网与 DNS，可用 `anet tool diag <host> 443` 分层定位 |

其他网络类失败的通用排查见 [故障排查与诊断](#/guides/troubleshooting) 与 [自我诊断](#/guides/doctor)。
