# 带内管理面

**管理流量当普通内网 HTTP 走数据面隧道**——控制台只是内网里的一个 web 站点。
不建中央控制台、不存全网会话：能否管理某节点 = 有没有到其 API 地址的通路。

## 控制台通道

GUI 内置 loopback 转发器（本地环回端口 → 客户端隧道 → 目标节点 API），
控制台窗口/浏览器打开 `127.0.0.1:58xxx` 即加载远端节点的管理 SPA，无需配浏览器代理。

```
控制台窗口 ──http──► 127.0.0.1:58xxx（loopback 转发器）
                     │  经本机已建立的客户端隧道（TLS 1.3）
                     ▼
                 目标节点 API（管理 SPA + REST）
```

- 端到端：管理 HTTP 在隧道 TLS 内传输，中继节点只见密文转发
- ACL 统一：收回规则/权限即失去管理通路
- 审计归因到人/到令牌：每条操作落真实身份

## 管理版接入链接（管理此节点）

控制台创建客户端账号时勾选「同时授予管理权限」，生成
`anet://connect?...&admin=1` 变体（生成页强警示 + `account.issue_admin_link` 签发审计）。

客户端连接后：

1. 配置响应带 `admin_console: true` → GUI 节点卡片出现「管理此节点」与「可管理」徽标
2. 点击后 GUI 经 `POST /api/v1/client/console-ticket` 取**一次性管理引导票据**（10 分钟，只存哈希）
3. 打开控制台窗口，SPA 以 `#boot=<ticket>` 经 `POST /api/v1/auth/admin-bootstrap` 换取管理会话
4. 换取即审计 `admin.console_access`（operator=`link:账号`）；收回权限即断开隧道、票据作废

## 暴露控制面（relay 链管理）

Relay Token 可勾选「允许该下游中继管理本节点」（默认关）+ ro/rules/full 三档。
握手时（AuthOk 向后兼容扩展）向该下游下发控制端点与管理引导票据：

```
上游 E ──握手下发 control──► 下游 D ──config.manageable──► 管理版客户端 C
   │                                                    │
   └──────── C 经隧道直达 E API，票据换取 scoped 管理会话 ◄┘
```

- 下游节点记录「可管理上游」并随其管理面下发 → **GUI 设备列表自动发现可管理节点（本机/已连节点/上游链）**
- 票据安全边界等同中继令牌本身：psk 持有者在数据面已是高信任凭据，暴露开关打开后凭中继会话直接换取管理会话（零开通）
- 换取审计 `admin.session_via_relay`（operator=`relay:psk_前缀@下游`）；吊销令牌 + 踢会话即全线回收

## scoped admin 三档

| 档位 | 能力 |
| --- | --- |
| `ro` | 只读（GET 状态/规则/账号/审计） |
| `rules` | 只读 + 路由规则增删改 |
| `full` | 全权（等同管理员） |

scope 随管理会话 JWT 签发，AdminAuth 层强制；未知档位 fail-closed 按只读处理。

## 路由再发布

GUI 同时开启客户端与服务端角色时，内嵌节点的 connector 会把**客户端隧道的规则转售给下游**：
通告集 = 静态配置 + 客户端规则值；下游 Open 命中这些规则时经对应客户端隧道转发（via=客户端隧道）。
规则集变化自动重连重新通告（不引入新帧类型，旧上游完全兼容）。

## 被否决方案存档（D 代理路线）

「C → D 控制台 → D 后端代理转发 → EFG」：D 须存全网 admin 会话（凭据库单点）、
EFG 审计只见 D 不见人、另需一套委托权限。保留为二期「有限委托管理」（转发带真实操作人身份头）的候选，
不作基础路径。
